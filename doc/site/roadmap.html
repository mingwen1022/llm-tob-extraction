实施路线：选型研究（核心）+ 多场景抽取产品（产品化层）

先在 CORD 上把"大模型 API vs 本地微调"的选型矩阵跑完（核心，单域即成立）；再横向加域 + 路由，包装成多场景私有化抽取产品。本页是 doc/plans/PLAN.md 的可视化。

共享基座 Qwen3.5-4B（锁死） 训练 HF PEFT 服务 vLLM 多 LoRA 数据 公开 gold，不手搓
核心命题
在数据不能出域的 to-B 文档抽取，微调后的本地小模型在"精度×成本×延迟×合规"帕累托前沿上胜过纯 prompt 和前沿 API。 选型研究在单域（CORD）就完整；多场景 Orchestrator 是可选的产品化 stretch，不是成立前提。

先厘清：「测不同裸模型」有两种角色，别混

角色是什么换不换目的
① 微调共享基座所有 adapter 冻结共用的底座锁死（Qwen3.5-4B，全程不换）保证一卡多 LoRA 热插拔
② 每域对照基线每域跑 base零样本/约束/你的LoRA/API每域重跑得出该域"本地 vs API"结论 → 驱动路由

模型选型能力体现在两处：(a) 一次性"共享基座 bake-off"选定 ①（Phase B）+ (b) 每域 API-vs-本地对照（②）。绝不每域重挑 fine-tune 基座——那会拆架构。

成本卖点：1 基座 + N 个几十 MB adapter vs N 个独立大模型 vs 按域调 GPT-4o。

分阶段计划

  1. Phase A · 核心 · P0

    补完 CORD 选型矩阵

    • E4 前沿 API 基线：GPT-4o + 国产（DeepSeek-V3/Qwen-Max）同集同评测器 ← 最关键
    • E1/E3 约束解码：vLLM guided_json 跑基座+LoRA 约束版
    • 加成本 + 延迟两列 → 写决策结论

    做完这步选型研究就完整（不依赖多场景）。

  2. Phase B · 核心

    共享基座 bake-off（一次性）

    CORD 上同一 LoRA 配方训 2–3 个候选基座：Qwen3.5-4B vs Qwen2.5-7B vs Llama-3.2-3B → "基座×F1×显存×速度"表 → 给"为什么锁 Qwen3.5-4B"补量化证据。只做一次，别每域重做。

  3. Phase C · 产品化

    加第二个域：合同（让"多域"变真）

    数据 CUAD（41 类条款）或 RealKIE-NDA。流程：先 dedup_check → span 标注转 JSON → 训同基座 r=16 adapter → 跑该域 E0–E4 对照。复用 shared/ 全流水线，只新写 convert_<域>.py + 注册 schema。

  4. Phase D · 产品化

    加第三个域：发票（含行项）

    数据 DocILE（6.7k / 55 字段 / 行项）或 RealKIE-FCC（11 字段）。同 Phase C 流程。

  5. Phase E · 产品化

    路由 + Orchestrator（中间模型）

    路由器三选一：(a) 句向量+轻量分类器 (b) 基座零样本判类 (c) 规则。vLLM 多 LoRA 热插拔。指标：路由准确率（混淆矩阵）+ 各域 F1 + 端到端 F1。

  6. Phase F · 呈现

    产品化 + 展示

    Gradio demo（这就是产品）：上传文档 → 自动识别类型 → 路由到本地 adapter → 出 JSON，并实时显示"本地 LoRA vs GPT-4o API"成本/合规对比。HF Space + HF Hub + 公开 repo + 站点产品页。

优先级与取舍

必做(核心选型研究):   Phase A ──► Phase B
产品化(PM 加分层):    Phase C ──► D ──► E ──► F
  • 只做 A+B：项目已成立。标题"单域抽取选型研究，架构为多域设计"。
  • 做到 C 以上：可正当叫"多场景私有化抽取产品 + 选型研究"，PM 叙事最完整。
  • 绝不手搓 gold；每个新域必须有公开数据集
  • 接入新域前先跑 shared/dedup_check.py（CORD 官方 split 有 8% 泄漏的教训）
  • 基座与训练格式锁死（Qwen3.5-4B + HF PEFT），中途别换
