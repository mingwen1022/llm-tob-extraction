结构化抽取评测指标详解

从 文本 → JSON 任务怎么打分：三层指标、数学定义、各维度逐一展开，全部用 CORD 真实数字（E0 基座 vs E2 LoRA）举例。

任务：收据 OCR → JSON test 集 100 条 评测器：shared/eval.py
三层指标，缺一不可
① JSON 合法率（能不能读、守不守契约）→ ② 字段级 P/R/F1（抽得准不准、全不全）→ ③ 聚合（micro / macro / per-field 三个角度）。 任何单一数字都会骗人，必须三层一起看。

0. 记号约定

对一条样本：金标准 JSON 记为 \(y\)，模型预测 JSON 记为 \(\hat{y}\)。两个核心算子：

  • 归一化 \(\nu(k, v)\)：把字段 \(k\) 的值 \(v\) 标准化（金额去逗号、日期统一、去空白大小写）。
  • 拍平 \(\Phi(\cdot)\)：把嵌套 JSON 展平成叶子 \((k,\nu)\) 对的多重集，并丢弃值为 null 的叶子。
\[ \Phi(y) \;=\; \big\{\,(k,\ \nu(k,v)) \;:\; (k,v)\ \text{是}\ y\ \text{的叶子},\ v \neq \texttt{null}\,\big\}_{\text{multiset}} \]

记 \(G=\Phi(y)\)（gold 多重集）、\(P=\Phi(\hat{y})\)（预测多重集）。列表用叶子字段名当 key、不带下标，所以顺序无关、靠多重集匹配。

1. 第一层：JSON 合法率

模型先得吐出"能用"的东西。分两级，分开报：

指标含义判定E0E2
可解析率 (parseable)能否 json.loads语法合法96%100%
schema 合法率 (valid)是否符合字段/类型契约Pydantic 校验通过26%100%
\[ \text{合法率} = \frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\big[\hat{y}_i\ \text{解析成功}\ \wedge\ \text{符合 schema}\big] \]
E0 可解析 96% 但 schema 仅 26% —— 差距来自基座把金额输出成数字（price: 60）而 schema 要求字符串。 E2 微调后 100%：微调本身就教会了格式纪律，约束解码都没用上。

2. 基本单位：(字段, 值) 多重集

字段级评分的原子操作 = 把两个 JSON 各自 拍平 + 归一化，再做多重集比对。用 test 集真实样本 index 3（甜甜圈小票）：

# INPUT: 1X @11000 / DONAT GULA 11,000 / SUBTOTAL 11,000 / TOTAL 11,000 / CASH 11,000
GOLD  Φ(y):                          PRED Φ(ŷ):  (E0 基座输出)
 (menu.nm,   "donat gula")            (menu.nm,   "@11000")      ← 抓错
 (menu.cnt,  "1x")                    (menu.cnt,  "1")           ← 丢了 X
 (menu.price,"11000")                 (menu.price,"11000")       ✓ 归一化后相等
 (sub_total.subtotal_price,"11000")   (sub_total.subtotal_price,"11000")  ✓
 (total.total_price,"11000")          (total.total_price,"11000")         ✓
 (total.cashprice,"11000")            (total.cashprice,"11000")           ✓
                                      (tax_price/service/change = null → 丢弃)
归一化救分的实例
PRED 的 total_price 原始是数字 11000，GOLD 是字符串 "11,000"。 经 \(\nu\)（去千分位）两者都 → "11000"，判为命中。没有归一化，这里会白白多 1 FP + 1 FN。

3. TP / FP / FN（多重集运算）

\[ \mathrm{TP} = |\,G \cap P\,|,\qquad \mathrm{FP} = |\,P \setminus G\,|,\qquad \mathrm{FN} = |\,G \setminus P\,| \]

（\(\cap,\setminus\) 为多重集运算，按出现次数计。）上面 index 3 的结果：

类别(字段, 值)计数
TP 命中menu.price、subtotal_price、total_price、cashprice4
FP 误报(menu.nm,"@11000")、(menu.cnt,"1")2
FN 漏报(menu.nm,"donat gula")、(menu.cnt,"1x")2

TP/FP/FN 不是成对的

很多人以为错一个字段必然同时进 FP 和 FN —— 只有"值替换错"才成对。三种情况：

情况例子FPFN
值替换错（同字段，值不同）gold nm=DONAT vs pred nm=@11000✅✅
纯漏抽（pred 少给/漏列表项）模型少抽一个菜品❌✅
纯多抽（pred 幻觉多余值）模型编一个 subtotal✅❌
铁证：E0 里字段 menu.nm 的 \(\mathrm{FP}=48,\ \mathrm{FN}=137\) —— 不相等，证明大量"纯漏抽"（模型少抽/抽串菜品，gold 的名字没有错值顶上）。 同一字段同一条里甚至能 TP/FP/FN 三者并存：gold 价 \(\{100,200\}\) vs pred \(\{100,999\}\) → 100 是 TP、999 是 FP、200 是 FN。

4. Precision / Recall / F1

\[ P=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}},\qquad R=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}},\qquad F_1=\frac{2PR}{P+R}=\frac{2\,\mathrm{TP}}{2\,\mathrm{TP}+\mathrm{FP}+\mathrm{FN}} \]
  • Precision（精确率）：你抽出来的，有多少是对的 → 低 = 多抽 / 抽错 / 幻觉。
  • Recall（召回率）：该抽的，抽到了多少 → 低 = 漏抽 / 少抽。
  • \(F_1\)：P 与 R 的调和平均，只要一个低就被拉下去（比算术平均更严）。

index 3（\(\mathrm{TP}=4,\mathrm{FP}=2,\mathrm{FN}=2\)）：

\[ P=\tfrac{4}{4+2}=0.667,\quad R=\tfrac{4}{4+2}=0.667,\quad F_1=0.667 \]

广义 \(F_\beta=(1+\beta^2)\dfrac{PR}{\beta^2P+R}\)；\(\beta>1\) 偏重 recall，\(\beta<1\) 偏重 precision。抽取一般用 \(\beta=1\)。

5. per-field：单字段自己的分

对每个字段 \(f\)，只用该字段（跨全部 100 条累计）的 \(\mathrm{TP}_f,\mathrm{FP}_f,\mathrm{FN}_f\) 算它自己的 P/R/F1。

\[ \mathrm{TP}_f=\sum_{i=1}^{N}\big|\{(k,v)\in G_i\cap P_i : k=f\}\big|,\quad F_1^{(f)}=\frac{2\,\mathrm{TP}_f}{2\,\mathrm{TP}_f+\mathrm{FP}_f+\mathrm{FN}_f} \]

E0 的 menu.nm（\(\mathrm{TP}=114,\mathrm{FP}=48,\mathrm{FN}=137\)）：

\[ P=\tfrac{114}{162}=0.704,\quad R=\tfrac{114}{251}=0.454,\quad F_1=0.552 \]

用途：定位短板。下表 E0 vs E2 各字段 F1：

6. micro-F1：所有字段倒进一个大池子

不分字段，把全语料所有 \(\mathrm{TP}/\mathrm{FP}/\mathrm{FN}\) 加总后算一次。

\[ \mathrm{TP}=\sum_{f}\mathrm{TP}_f,\quad \text{micro-}P=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}},\quad \text{micro-}F_1=\frac{2\,\mathrm{TP}}{2\,\mathrm{TP}+\mathrm{FP}+\mathrm{FN}} \]

E0 全 test 集：\(\mathrm{TP}=377,\ \mathrm{FP}=413,\ \mathrm{FN}=678\)：

\[ \text{micro-}P=\tfrac{377}{790}=0.477,\quad \text{micro-}R=\tfrac{377}{1055}=0.357,\quad \text{micro-}F_1=\tfrac{2\cdot377}{2\cdot377+413+678}=0.409 \]

特点：每个字段实例权重相等 → 高频字段（menu.* 几百实例）主导。代表"整体抽对了多少个值"。

7. macro-F1：各字段 F1 的平均

\[ \text{macro-}F_1=\frac{1}{|\mathcal{F}|}\sum_{f\in\mathcal{F}}F_1^{(f)} \]

E0 共出现 \(|\mathcal{F}|=15\) 个字段（含 6 个 F1=0 的"幻影字段"，是基座把结构嵌套错位造出来的）：

\[ \text{macro-}F_1=\frac{0.557+0.552+0.291+0.381+0.324+0.277+0.331+0.416+0.373+6\times0}{15}=\frac{3.501}{15}=0.233 \]

特点：每个字段权重相等（不管它出现 200 次还是 4 次）。小字段、幻影字段都平等计入 → 比 micro 更能暴露"个别字段很烂"。

8. micro vs macro：什么时候看哪个

算法谁主导考试类比
micro所有 TP/FP/FN 合并算一次高频字段全班所有题汇总算总正确率（答题多的人影响大）
macro各字段 F1 先算再平均每字段一票每人先算自己分，再人均（每人一票）
per-field单字段自算—看每章单独考多少
E0 为何 micro(0.41) > macro(0.23)：大字段 menu.nm/cnt（量大、F1≈0.55）把 micro 抬高；macro 里一堆小字段 + 0 分幻影字段平等参与，把平均拉低 → "整体还行，但部分字段很差且不均衡"。
E2 微调后 micro(0.950)≈macro(0.955) → 幻影字段消失、各字段都好，变均衡了。

11. 扩展到多域：同一套 Φ/TP-FP-FN 逻辑，换个 schema 直接套用

上面 §1-10 全部用 CORD 举例（英文小票、扁平嵌套 schema）。Phase C 又做了两个中文域——DuEE-fin（金融公告，schema 带事件列表）和 CCKS-fraud（反欺诈案例，纯扁平 schema）。 评测器 shared/eval.py 代码一行没改，因为 §0 的拍平算子 \(\Phi\) 天然处理嵌套/列表/扁平——这正是"schema 注册制"设计的意义。下面两个例子都是 test 集真实样本、模型真实输出（runs/duee_e0.jsonl / runs/duee_e2.jsonl / runs/ccks_e0.jsonl / runs/ccks_e2.jsonl），TP/FP/FN 用 shared/eval.py 的 flatten() 现算，不是手工编的。

附录：三条保证指标"真实"的规则

  • 归一化 \(\nu\)：金额去千分位/货币符号、日期统一 ISO、去空白、大小写、全半角 → 否则格式差异被误判为错。
  • 空值约定：值为 null/空 的叶子在 \(\Phi\) 中丢弃（不计入分母），否则一堆空字段刷虚高。
  • 列表多重集、不带下标：菜品顺序不影响打分（按 \((k,v)\) 多重集匹配）。
