2. 逐部位设计与逻辑

2.1 Tokenizer + Embedding（vocab 248320）

  • 是什么：文本切 token → 查表成 2560 维向量；图片经视觉塔后也映射到同一空间，拼进序列。
  • 为什么大词表：覆盖 多语言（200+）+ 多模态特殊 token（<image>、<vision_start> 等）。
  • 对我们：CORD 是英文/数字小票，词表绰绰有余；Embedding 冻结。

2.2 视觉塔 ViT（24 层）+ merger

  • 是什么：标准 ViT，图片切 16×16 patch → 编码 → merger 合并降数量 → 投影成「视觉 token」喂进主干。
  • 为什么有它：Qwen3.5 原生多模态，图文走同一个 decoder。
  • 对我们：Phase 1–4 只用文本，视觉塔整块冻结/不加载；Phase 5 做「图片→JSON」时正是复用这块（也是我们选 Qwen3.5 的原因）。

2.3 主干：混合注意力（核心设计）

32 层里 3 线性 + 1 全注意力 循环。这是整个架构最关键的取舍。

a) Gated DeltaNet 层（线性注意力，占 75%）
  • 是什么：线性/循环式注意力。不像标准注意力"每个 token 看全部历史"（\(O(n^2)\)），而是维护一个固定大小的状态矩阵，逐 token 用「delta 规则」更新，再加门控控制旧状态衰减/遗忘。
  • 逻辑：delta 规则 ≈ 在线学习一张"关联记忆表"，新信息修正旧关联；门控 ≈ 记多久、忘多快（类似 LSTM 遗忘门）。
  • 为什么用：复杂度接近线性，显存/计算不随长度二次爆炸 → 支撑 262K~1M 上下文。
  • 代价：固定状态容量有限，对"精确回忆远处某细节"较弱。
b) Full Attention 层（全注意力，占 25%）
  • 是什么：标准 softmax 自注意力 + GQA（16 Q 头共享 4 组 KV）+ RoPE。
  • 为什么保留 1/4：能精确检索任意位置，补线性层"记忆模糊"的短板。每 4 层做一次全局精确对齐。
  • 设计哲学：线性层"高效带着压缩记忆往前走"，全注意力"需要时精确回头查" —— 省钱 + 不丢精度的折中。

对我们抽取任务：小票/合同不长，长上下文用不太到；但全注意力层对"从文本精确定位字段值"很重要——这正是抽取需要的能力。

2.4 MLP（SwiGLU：gate/up/down_proj）

  • 是什么：注意力之后的前馈网络。SwiGLU = down( SiLU(gate(x)) * up(x) )，两条上投影（gate/up：2560→9216）门控相乘，再下投影（down：9216→2560）。
  • 逻辑：注意力"token 之间混信息"，MLP"每个 token 内部做非线性变换/存知识"。
  • 占参数大头：9216 中间维 → 微调调 MLP 收益高。

2.5 RMSNorm + 残差

每个子层前做 RMSNorm（比 LayerNorm 轻），输出加残差；Pre-Norm 结构，稳定训练。冻结不调。

2.6 Dense vs MoE

  • 4B 是 dense：每层 MLP 单个 SwiGLU，所有参数都参与。
  • 大模型（35B/122B/397B）是 MoE：MLP 换成多专家 + 路由，每 token 只激活少数专家。
  • 对我们：dense 4B 没有路由/专家，结构简单，微调和 vLLM 多 LoRA 都更省心（MoE 才有 fused-expert 兼容坑）。

2.7 LM Head

final RMSNorm → 线性层 2560→vocab，输出每个 token 概率。冻结不调。

3. 我们 LoRA 调哪几层

LoRA = 冻结基座，在选定线性层旁挂低秩旁路（A·B，r=16）。按名字匹配。

部位模块在哪些层LoRA
全注意力q_proj / k_proj / v_proj / o_proj8 个全注意力层✅
MLPgate_proj / up_proj / down_proj全部 32 层✅
GDN 内部 q/k/v 投影（命名依实现而定）24 个线性层⚠️ 命中则调
GDN 门控/衰减/卷积b_proj/decay/conv 等24 个线性层❌ 冻结
Embedding / LM Head / RMSNorm—全局❌ 冻结
视觉塔 ViT + merger—视觉❌ 冻结
✅ 实测确认（本项目训出的 adapter）
解析我们训好的 adapters/cord/：共 128 个 LoRA 模块，覆盖 全部 32 层 MLP（gate/up/down） + 8 个全注意力层的 q/k/v/o；24 个 GDN 层的内部投影命名不同，未被命中（冻结）。 adapter 的 key 形如 ...model.language_model.layers.X...（VL 结构，语言主干在 language_model 下）。
建议：混合架构上用 all-linear 保证覆盖
target_modules = "all-linear"   # 命中所有 nn.Linear（含 GDN 投影），只排除 LM head
这样 24 个 GDN 层不会被漏掉。验证： 
print({n.split('.')[-1] for n,_ in model.named_modules() if 'proj' in n})  # 真实投影名
model.print_trainable_parameters()                                         # 可训练参数占比

4. 这套架构为什么适合（也限制）我们的任务

特性对结构化抽取的意义
线性注意力(75%) → 长上下文小票/合同不长，优势用不太到；长合同（RealKIE）时有用
全注意力(25%) → 精确检索关键：抽取就是"从文本精确定位字段值"，靠这些层
dense 4B结构简单，LoRA + vLLM 多 LoRA 最省心
原生多模态Phase 5 复用同基座做图片→JSON，不换模型
Apache 2.0训出的 adapter/模型可放简历/产品，无 license 顾虑
