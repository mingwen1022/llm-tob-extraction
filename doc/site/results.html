三域评测结果

三个语言、任务结构、数据来源完全不同的域，用同一套微调配方（Qwen3.5-4B + LoRA r=16/alpha=32）、同一套评测器（shared/eval.py）实测出来的完整数字。CORD 详细的"vs 5个大模型API"选型对比见总览页；这里聚焦"微调本身有没有效、能不能推广到多个域、多域组合成 Orchestrator 后精度会不会掉"。

3 域独立验证 微调提升 +0.49~0.54（稳定） 3域路由准确率 98.9% 端到端延迟 ~8s/条（Mac未优化）

3. Orchestrator 端到端结果（多域组合后精度会不会掉？）

架构：文本 → 路由（Qwen3.5-4B 零样本判类，零训练分类器）→ 选对应 adapter+schema → 共享基座 + PEFT 多adapter（set_adapter()切换）→ 抽取 → 标准化 JSON。一个基座常驻，多个 LoRA 按需切换——本质与 vLLM --enable-lora 多LoRA服务同一概念。

4. 关键工程发现摘录

  • 路由不用训练分类器——基座零样本判类即可达到 98.9%~100% 准确率，可扩展到更多域
  • PEFT 原生支持多 adapter 同时加载 + set_adapter() 切换，本质与 vLLM --enable-lora 多LoRA服务同一概念
  • Qwen3.5 的 GDN（Gated DeltaNet）层需装 fla + causal-conv1d 加速核，否则慢 15 倍以上
  • 248,320 大词表导致长序列 fp32 logits 转换易 OOM，需降 batch/max_seq_len 应对
  • T4（Turing）无法有效训练该模型（bf16 不支持），需换 Ampere+ 架构（L4）
