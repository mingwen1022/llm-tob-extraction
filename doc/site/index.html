面向本地私有化部署的 to-B 文档抽取

一个"用大模型 API 还是本地微调小模型？"的模型选型 + 评测研究，并包装成多场景私有化抽取产品。面向 AI 产品经理岗（to-B / fintech）。

基座 Qwen3.5-4B + LoRA 数据 公开 gold（CORD…） 评测 自建字段级 P/R/F1 服务 vLLM 多 LoRA
核心命题（Thesis）
在数据不能出域的 to-B 文档抽取场景，微调后的本地小模型，在"精度 × 成本 × 延迟 × 合规"的帕累托前沿上，胜过纯 prompt 和前沿大模型 API。 项目价值不来自"LoRA 训得多难"，而来自把一次微调包装成有对比、有取舍、有结论的选型决策。

决策结论
在数据不能出域的金融文档抽取上，微调的本地 4B 小模型在精度（0.945，超全部大模型 8-16 点）、成本（$0 边际）、合规（可私有化、不出境）三个硬轴上全面胜出——这才是金融场景对的选择。延迟当前未优化、不作为卖点。

已验证的关键结果

  • 本地 4B LoRA（0.945）超过全部 5 个前沿/国产大模型 API（最高 Gemini 0.866），且 $0 边际成本、可私有化
  • 微调 vs 大模型 vs prompt 全跑过：prompt 写到最全基座也只 0.647，通用大模型最高 0.866，唯有微调到 0.945 —— 证明"专家小模型 > 通才大模型"
  • "格式问题该微调、不是知识问题该 RAG"：基座把金额输出成数字（type 错）→ 微调直接解决，教科书级判断案例
  • 方法论诚实：控制变量（同集/同评测器/同完整prompt/去泄漏92条）+ 如实标注局限（思考模式未统一、本地延迟未优化）
