方案① 合同 / 票据 结构化抽取 → JSON

把非结构化文本抽成标准 JSON。toB 最高频的付费需求，最适合作为简历主打项目。

难度 ★★☆☆☆ 成本 $0–5 算力 Mac MLX 即可 toB 价值 ★★★★★ 工期 4–6 天

一句话定位

输入一段合同 / 发票 / 简历文本，模型输出固定 schema 的 JSON（如合同的甲乙方、金额、签署日期、违约条款）。配 JSON-Schema 约束解码，保证输出 100% 合法可解析。

为什么对 toB 有说服力

  • 这是企业自动化最高频的需求：财务、法务、HR、供应链都在做文档结构化
  • 能展示「可靠性工程」：约束解码保证 JSON 永远合法 —— 这是落地真痛点
  • 能算清 ROI：自家小模型 vs 调 GPT-4o 的成本差，直接体现工程价值
  • 私有化诉求强：合同/财务数据不能上公有云，正好是小模型私有部署的卖点

推荐数据策略
选一个垂类（建议合同条款，最 toB）。用 CUAD 真实数据 + GPT-4o 造数 混合，目标 1000–1500 条训练 / 200 条验证 / 200 条测试。测试集必须人工校对，否则指标不可信。

详细实施步骤

  1. Phase 1 · 数据

    定义 JSON Schema + 造数据

    先用 Pydantic / JSON-Schema 把目标字段定死（如 party_a, party_b, amount, sign_date, term, penalty）。再写 build_data.py 调 GPT-4o 批量造 (合同文本 → JSON) 对，并混入 CUAD。

    # build_data.py 核心：让大模型按 schema 输出
SYSTEM = "你是合同信息抽取器，严格按给定 JSON schema 输出，缺失字段填 null。"
# 输出存成 MLX 对话格式 data/train.jsonl
{"messages":[
  {"role":"system","content": SYSTEM + SCHEMA_STR},
  {"role":"user","content": contract_text},
  {"role":"assistant","content": json.dumps(fields, ensure_ascii=False)}
]}
  2. Phase 2 · 基线

    先测基座模型（建立对照）

    在 不微调的 Qwen3.5-4B 上跑测试集，记录字段 F1 和 JSON 合法率。这是你后面要超越的对照组，简历对比表的第一列。

  3. Phase 3 · 训练

    Mac 上 MLX LoRA 微调

    mlx_lm.lora --model Qwen/Qwen3.5-4B --train \
    --data ./data --batch-size 4 --iters 1500 \
    --learning-rate 1e-4 --adapter-path ./adapters
mlx_lm.fuse --model Qwen/Qwen3.5-4B --adapter-path ./adapters \
    --save-path ./fused_model

    M1 Max 64G 跑 4B LoRA 完全够；若想要更强可换 8B。Colab 也可用 Unsloth 跑同样数据做对比。

  4. Phase 4 · 可靠性

    接入 JSON-Schema 约束解码

    用 Outlines 强制模型只能生成符合 schema 的 token，JSON 合法率直接拉到 ~100%。这是本项目最大的工程亮点。

    import outlines
model = outlines.models.transformers("./fused_model")
generator = outlines.generate.json(model, ContractSchema)  # Pydantic 类
result = generator(contract_text)   # 保证是合法 ContractSchema 实例
  5. Phase 5 · 评测

    字段级评测 + 三方对比

    写 eval.py：逐字段算 Precision / Recall / F1（注意做归一化：日期格式、金额单位、大小写）。对比 ① 基座 ② 你的微调模型 ③ GPT-4o。

  6. Phase 6 · 交付

    Demo + 部署 + 文案

    Gradio 做一个「贴文本 → 出 JSON + 高亮字段」的 demo，上传 HF Space。llama.cpp 量化成 GGUF 证明能端侧/私有部署。写 README + 简历 bullet。

避坑清单

  • 测试集别用 GPT-4o 造的 —— 会高估指标，必须人工校对
  • 评测做字段归一化（日期/金额/空白），否则 F1 被格式问题拖低
  • schema 别太大，先 6–10 个核心字段跑通，再扩展
