方案② Text2SQL（自然语言转 SQL）

业务人员用大白话查数据库。企业 BI 刚需，且有公开 benchmark 能出客观硬指标。

难度 ★★★☆☆ 成本 $15–30 算力 GCP L4/A100 toB 价值 ★★★★☆ 工期 6–9 天

一句话定位

输入「上个月华东区销售额前十的产品」+ 数据库表结构，模型输出可执行的 SQL。用 execution accuracy（执行结果对不对）而非字符串匹配来评测。

为什么对 toB 有说服力

  • 企业 BI / 数据中台高频需求，几乎每家数据公司都在做
  • 有公开榜单（BIRD / Spider），指标客观可信，简历最硬
  • 能展示进阶工程：schema-linking、SQL 执行校验、自我纠错重试
  • 难度梯度好：从单表查询到多表 JOIN、嵌套子查询，可层层展示能力

技术架构

用户问题 + DB Schema
   │  schema-linking（挑相关表/列，压缩 prompt）
   ▼
[ Qwen3-7B/8B + LoRA 微调模型 ]
   │  生成 SQL
   ▼
在真实 DB 上执行 ──失败──► 把报错喂回模型，self-correction 重试
   │成功
   ▼
结果 ──► execution accuracy 评测 ──► 三方对比表

数据来源（全公开、有官方评测脚本）

数据集说明用途
BIRD大规模真实数据库，含脏数据，难度高、最贴近企业主力训练 + 评测（含金量最高）
Spider 1.0跨域 Text2SQL 经典基准入门 + 对比基线
CSpiderSpider 中文版做中文 Text2SQL 叙事
建议
主攻 BIRD（最能体现企业真实复杂度），用官方 dev set 报 execution accuracy。中文岗位可加做 CSpider 增加差异化。

详细实施步骤

  1. Phase 1 · 数据

    下载 BIRD/Spider，转成训练格式

    把 (question, db_schema) → SQL 组织成对话样本。schema 用 CREATE TABLE 文本表示，附带几行样例数据帮助模型理解列含义。

  2. Phase 2 · 基线

    跑基座 + 大模型基线

    记录 Qwen3-8B 基座 与 GPT-4o 在 dev set 的 execution accuracy。作为对照组。

  3. Phase 3 · 训练

    GCP 上 LoRA 微调 7B/8B

    7B/8B 显存较大，用 GCP L4（QLoRA）或 A100。推荐 LLaMA-Factory 配置式启动：

    # config.yaml 关键字段
model_name_or_path: Qwen/Qwen3-8B
finetuning_type: lora
lora_target: all
dataset: bird_train
cutoff_len: 4096
learning_rate: 1.0e-4
num_train_epochs: 3

# 启动
llamafactory-cli train config.yaml

    先在 Colab 用 1–2k 子集验证 pipeline 跑通，再上 GCP 跑全量，省额度。

  4. Phase 4 · 执行校验

    self-correction 重试机制

    生成的 SQL 在真实 DB 上执行；若报语法错/超时，把错误信息拼回 prompt 让模型改一次。这一步能显著提分，也是工程亮点。

  5. Phase 5 · 评测

    execution accuracy（官方脚本）

    用 BIRD/Spider 官方 test-suite 评测：比较你的 SQL 执行结果与标准答案结果是否一致，而非比字符串。这是 Text2SQL 的金标准。

  6. Phase 6 · 交付

    Demo + 文案

    Gradio：上传一个 SQLite 示例库 → 用户提问 → 显示生成 SQL + 执行结果表格。最直观的演示。

避坑清单

  • 别用字符串匹配评测 SQL —— 同一查询写法很多，必须用 execution accuracy
  • prompt 里 schema 太长会爆 context，做 schema-linking 裁剪
  • 先在 Colab 小样本验证 pipeline，再上 GCP，避免烧额度调 bug
